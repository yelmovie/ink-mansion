# 학생 입장 플레이 점검 — 잉크저택 (2026-10-18, 라이브 배포본)

> 대상: https://ink-mansion.vercel.app (커밋 db8ca8f 배포본) · 방법: 내장 브라우저로 1단계~완성실까지 직접 플레이
> 뷰포트: 1280×800(태블릿, 전 화면) · 906×755(폴드/고DPR, P1·P3·P7·P10) · 1920×1080(전자칠판, P3)
> 코드는 수정하지 않았다. 아래는 발견 사항과 권장 수정이다.

## 발견 사항

### P0 — 조작 불가
없음. 10개 방 모두 끝까지 진행됐고 콘솔 오류는 GLB 404 폴백 1종뿐.

### P1 — 주요 화면 깨짐 / 태블릿에서 실제로 불편한 것

1. **본문 글자가 태블릿에서 13.6px, 폴드에서 9.6px로 렌더링된다.**
   - 원인: DOM 오버레이가 논리 1600px 고정 + `transform: scale(화면폭/1600)`. CSS 17px 본문이 1280에서 0.8배, 906에서 0.566배로 줄어든다. "글은 자동으로 저장돼"(12px)는 1280에서 9.6px.
   - 전자칠판(1920)은 1.2배라 통과하지만, 교실 태블릿이 주 기기라서 FAIL.
   - 권장: 본문·안내 계열을 17 → 21~22px, 보조 라벨 12 → 16px로 올린다(1280에서 16px 이상 확보). 글자가 커진 만큼 노트 패널의 안내문을 줄인다(P2-3).
   - 근거: `src/ui/AppShell.ts` 오버레이 스케일, `src/styles/ui-kit.css` 폰트 토큰
2. **터치 영역이 태블릿에서 44px 미만.** 1280 기준 렌더 크기: 힌트 85×38, 소리/설정/홈 38×38, 건너뛰기 91×38, 글쓰기 탭 54×35, 장면 태그 44×27, 저장하기 96×27, 전체화면 아이콘 27×27. 906에서는 전부 20~30px대.
   - 권장: 아이콘 버튼 min 48px(논리 60px), 저장하기·태그 min-height 44px(논리 56px).
3. **P3 해석실: 카드를 다른 카드 위에 놓으면 두 카드가 겹친 채 멈춘다.** 실이 보이지 않고 ✕ 버튼이 겹친 카드 사이에 묻힌다. 끌어서 떼어내면 정상이지만 학생은 "사라졌다"고 느낄 수 있다.
   - 권장: 드롭 성공 시 끌던 카드를 원래 자리로 되돌리거나, 대상 카드에서 120px 이상 떨어진 위치로 밀어낸다. `src/pages/page03Interpret.ts` dragend.

### P2 — 가독성·안내 품질

1. **P7 글쓰기에 글자수 표시가 없다.** 단계별 게이지가 42×6px 막대뿐이라 "얼마나 더 써야 하는지" 알 수 없다. P9 결말에는 "125자" 표시가 있어 일관성도 깨진다. 업체 피드백(글자수)과 직결.
   - 권장: 탭 옆 또는 노트 하단에 "지금 N자 · 문이 열리려면 400자" 한 줄. `src/pages/page07Writing.ts` hint.
2. **P3 실 위 질문 입력칸이 한 줄 input이라 글이 오른쪽으로 잘린다.** ("모래시계가 거꾸로 돌 때마다 종이가 소…") 가설 칸은 textarea인데 이 칸만 다르다.
   - 권장: textarea 2줄로 통일.
3. **노트 패널 안내문이 너무 길다.** P3 해석 노트는 첫 입력칸 전에 8줄(설명 2문장 + 질문 + 예시 2줄 + 라벨). P2도 질문·예시·경고 3덩어리. 글자를 키우면 더 넘친다.
   - 권장: 예시는 접기(▸ 예시 보기), 설명 문장은 강아지 대본으로 이관.
4. **P6 뼈대 카드 메모가 말 중간에서 잘린다** ("...냄새로 기억을 읽는 강아", "...소용돌이로"). 말줄임표가 없어 저장이 안 된 것처럼 보인다.
   - 권장: `-webkit-line-clamp: 2` + `text-overflow: ellipsis`, 또는 어절 단위 자르기 + "…".
5. **P8 퇴고: 문장이 눌리는 것처럼 보이지 않는다.** `.rev-sent`에 cursor:pointer 외 시각 단서가 없다(태블릿에서 커서는 무의미). 첫 안내를 읽지 않으면 뭘 눌러야 하는지 모른다.
   - 권장: 점선 밑줄 또는 연한 하이라이트, 첫 문장에 "눌러서 고치기" 뱃지 1회.
6. **P4 씨앗: 카드를 고른 뒤 소켓 라벨이 소켓 그림 위에 겹쳐 읽기 어렵다** ("물건의 냄새를 맡으면 그 물건의 기억이 보여요"가 어두운 소켓 위에 깔림).
   - 권장: 라벨 뒤에 반투명 판, 또는 첫 8자 + "…"로 축약하고 전체는 오른쪽 노트에서.
7. **"저장하기" 버튼과 "글은 자동으로 저장돼"가 같은 패널에 같이 있다.** 자동 저장이면 버튼은 혼란만 준다.
   - 권장: 버튼을 빼거나 "다음 칸으로"처럼 실제 동작으로 바꾼다.
8. **P6 타이틀 플라크 "3단계 · 이야기 뼈대 짜기"가 2줄로 꺾여 "짜기"만 고립.** 1280에서 확인.
   - 권장: 문구를 "뼈대 짜기"로 줄이거나 플라크 폭을 넓힌다.

### P3 — 개선 권장

1. 강아지 대본 위치 표현이 실제와 다름: P1 "오른쪽 위 가방으로"(가방은 상단 중앙), P7 "오른쪽 노트에"(노트는 중앙). `src/data/hints.json`
2. 타이틀 이어하기/새 이야기, P4 카드 7장, P7 단계 탭 4개에 접근성 이름이 없다(스크린리더·자동화 둘 다 빈 버튼으로 잡힘). `aria-label` 추가.
3. P8 잉크 괴물 "잉크 오염 N단계" 라벨이 강아지 말풍선과 같은 자리에 떠서 말풍선이 열릴 때 가려진다.
4. P2 진입 때마다 `/models/clue-*.glb` HEAD 404가 콘솔에 남는다(2D 폴백은 정상). 모델이 없는 단서는 manifest에서 미리 걸러 요청 자체를 막으면 깔끔하다.
5. P5 사건을 담은 뒤에도 오른쪽 패널 "이 사건 담기" 버튼 문구가 그대로다. "✓ 담김" 표시가 있으면 좋다.

## 점검하지 못한 것

- P1 문지르기 손맛(22→34회 포인터 이동), P10 제본 핸들 회전 — 합성 입력으로는 재현이 안 돼 실기기 손가락 확인 필요.
- 애니메이션 타이밍(카드 뒤집기·배지 등장) — 내장 브라우저 창이 1fps로 돌아 판단 불가. 코드상 타이머는 정상.
- 가로→세로 회전 안내, 카톡 인앱 브라우저(873×580), 파일 저장·인쇄 다운로드.
- 30명 동시 접속·오프라인(classroom-ready 영역).

## 요약 — 먼저 고칠 3가지

1. 글자 크기(P1-1)와 터치 크기(P1-2) — 오버레이 스케일 구조 때문에 토큰 값만 올리면 전 화면에 한 번에 반영된다.
2. P7 글자수 표시(P2-1) — 업체가 또 물어볼 항목.
3. P3 카드 겹침(P1-3) — 학생이 "카드가 사라졌다"고 말할 가능성이 높다.
